從零認識
大型語言模型

LLM 如何把文字轉成模型能處理的形式，又如何一步步生成回答？

先建立一個觀念：LLM 很擅長生成語言，但「說得流暢」不代表「內容一定正確」。

本簡報以本專案 LLM Wiki 為知識來源。

01｜基本概念

LLM 是什麼？

大型語言模型（Large Language Model, LLM）是一種從大量資料中學習語言模式，並根據上下文預測 token 序列的模型。

大量資料

讓模型接觸多樣的語言用法與資訊模式。

大量參數

參數是模型在訓練中調整的數值，用來表示學到的模式。

上下文

模型會利用前後文，判斷接下來較可能出現什麼。

想像句子：「下雨了，出門記得帶……」模型會根據上下文評估「雨傘」等接續內容的可能性。
02｜文字如何進入模型

Token、Tokenizer、Embedding

模型不會直接把整句話當成一個單位，而是先依 tokenizer 規則切成 token。

示意例子｜中英混合文字

「Hi，今天吃 apple？」可能被切成類似以下片段：

Hi，今天吃apple？

這是概念示意，不是特定模型實際 tokenizer 的輸出；實際切法會因模型與詞彙表而不同。

英文

常見單字可能是一個 token，也可能拆成子詞片段。

appleplaying（示意）

中文

可能依詞彙或字元切分，不一定按照日常認定的詞語切。

今天吃蘋果
文字→Tokenizer 切分→Token ID→Embedding 向量

Token ID 是詞元對應的編號；Embedding 把編號轉成模型可運算的數值向量。

03｜核心架構

Transformer：參考上下文

自注意力（Self-attention）讓模型在理解一個詞時，也能參考同一句中的其他詞。

點選句子，觀察「蘋果」會參考哪些詞
蘋果放在桌上
目前語境：水果

「桌上」提供物品擺放位置的線索，有助於判斷「蘋果」是水果。

桌上
放在

權重條是概念示意，不是模型實際計算出的注意力數值；實際注意力分布會更複雜。

為什麼需要自注意力？同一個詞可能有不同意思，模型需要利用上下文線索，而不是只看單一詞語。

Encoder 與 Decoder 是 Transformer 常見元件；不同模型可能採用不同組合。

04｜模型如何學習

預訓練：考前長期練功

預訓練就像考前練習：模型透過大量例子調整參數，逐漸學習語言模式。

訓練階段

📚 考前練功

接觸大量訓練資料

預測並計算誤差

調整模型參數

使用階段

📝 現場作答

使用者輸入提示

模型依上下文產生回答

回傳生成結果

目標：完成當下任務

關鍵差異：預訓練會透過訓練程序調整參數；一般推論／生成時，通常使用已訓練好的參數產生輸出。

許多自回歸模型常以根據前文預測下一個 token 作為訓練目標；不同模型的訓練目標可能不同。

05｜模型如何回答

逐步生成文字

推論時，模型會依照目前上下文，一步一步接出後續 token。

互動示範｜按「生成下一步」看句子接龍

提示：今天下雨了，出門記得帶

今天下雨了，出門記得帶＿＿
0 / 3 步

每按一次，示意模型產生一個後續片段。

讀取上下文→預測 token→加入句子↻再次預測

此互動是教學示意，不會真的呼叫 LLM；實際生成也會受到解碼策略與系統設定影響。

06｜調整模型與使用方式

提示詞、微調、蒸餾有何不同？

三種方式都能讓模型更符合需求，但「改變的東西」不一樣。

不改模型參數

提示詞設計｜給模型清楚指令

情境：請 AI「用 100 字、條列式，向國中生解釋什麼是 LLM」。

做法：補充任務、背景、格式或範例，引導模型回答。

特色：通常最快上手，不需要重新訓練模型；效果會受提示內容影響。

提示詞

改變「這次怎麼問」

通常不需訓練

微調

用特定資料進一步訓練，改變模型參數

需要資料與算力

蒸餾

讓較小模型學習較大模型的輸出或能力

著重效率取捨
07｜能力與限制

為什麼不能完全相信 LLM？

幻覺

可能產生看似合理、實際卻錯誤或缺乏依據的內容。

偏誤

可能反映訓練資料中的偏見或不平衡。

時效性

模型不一定掌握最新資訊，需確認資料日期。

資源成本

訓練與推論都可能需要大量運算資源。

重要提醒：回答流暢不等於事實正確。重要資訊應回到可靠來源查證。
08｜負責任使用

使用 LLM 的四個好習慣

  • 把模型當成協助整理與思考的工具，而不是唯一權威。
  • 重要數據、日期、人物與研究結論要查原始來源。
  • 提供清楚的背景與限制，讓問題更具體。
  • 避免輸入不必要的個人資料或機密內容。
好的使用方式不是盲目相信 AI，而是善用它的效率，同時保留自己的判斷。
